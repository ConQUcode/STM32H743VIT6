 遥控器接收模块 (Remote) 重构说明
为了在 FreeRTOS 系统下最大限度利用 CPU，遥控器数据解析已完全摒弃阻塞式与单字节中断读取，采用了极低耦合的 **“非阻塞硬件 DMA + RTOS 任务通知”** 架构。
**核心特性：
* **零系统开销**：使用 `HAL_UARTEx_ReceiveToIdle_DMA`，由 USART6 DMA 硬件后台静默搬运定长 18 字节的数据帧，期间不占用任何 CPU，单帧传输结束后才触发一次空闲中断。
* **RTOS 深度解耦**：空闲中断触发后仅向任务队列发送唤醒信号 (`osThreadFlagsSet`) 即刻重启 DMA；实际的大端转小端数据解算 (`Remote_Parse`) 会交由独立的 FreeRTOS 任务完成，中断极度轻量，绝不影响实时控制。
* **极简式调用**：
  1. 应用初始化层调用 `RemoteControlInit();` 即可自动绑定 UART6 与中断任务。
  2. FreeRTOS 解算任务(`StartRemote`)的死循环内调用 `RemoteControlTask();` 将自动实现挂起与阻塞解析，等待帧到来。
* **实时调试窗口**：应用层可直接将 `test_remote` 或 `remote_dev` 指针加入 Debug 模式的 Watch 变量窗口，随时展开点选并观测 `data` 内摇杆、拨轮、开关的实时整型数据变化。

2026/5/17 CAN2 ID=3 的 GM6020 上电疯转问题处理：
* 在 `APPLICATION/chasis.c` 中给 CAN2 ID=3 的转向 GM6020 增加单独上电保护 `ChassisSteeringId3StartupGuard()`。该电机反馈未初始化时保持停止；反馈就绪后先抱住当前角度若干控制周期，再进入正常转向闭环，避免上电直接大电流追零。
* 新增 `CHASSIS_GM6020_ID3_OUTPUT_REVERSE` 开关，目前为 `1U`。该开关只作用于 CAN2 ID=3 的 GM6020，用于修正该电机最终电流输出方向和软件默认方向相反的问题；若实车验证方向不对，可改为 `0U` 再试。
* 在 `MOUDLE/motor/motor_def.h` 中为 DJI 电机控制设置增加 `output_reverse_flag`，并在 `MOUDLE/motor/dji_motor.c` 中于 PID 计算完成后反向最终输出电流。该字段默认为 0，不影响其它电机。
* 修正上电保护过度锁车的问题：保护逻辑不再要求四个 6020 全部反馈就绪，也不再提前 `return` 整个底盘解算。现在遥控器仍会驱动其它正常电机；当 ID=3 未 ready 时，仅暂时屏蔽对应左后驱动轮速度，避免未受控转向下强行行走。
* 给 `DJIMotorEnable()`、`DJIMotorStop()`、`DJIMotorSetRef()` 增加空指针保护，提高电机初始化异常时的容错性。
